# 通用滚轮：安装、认证与验收

## 使用约定

鼠标放在哪里，表冠就像在那里转普通滚轮。应用生成公开的竖向像素滚轮事件，由 macOS 正常路由。它不判断当前浏览器、网页正文、前台应用或窗口目标。腕控自身在后台或最小化不影响资格；关闭腕控窗口仍会退出整个电脑程序。

系统输出初始暂停。屏幕按钮发送明确的启用／停用请求，不是重复一次会把结果反过来的切换指令。系统发送成功只表示调用了提交接口，不能据此确认接收应用或屏幕更新。不同应用对像素滚轮的响应需要实际校准。

## 单对设备配置（开发安装者）

这轮采用每对设备独立的 256 位随机密钥。它只用于已知开发设备的试用，不是完整的消费者配对流程。源码和两个应用包都不含密钥；不能将一份通用密钥分发给多个人。

1. 确认两端已使用自己的团队签名并安装。Mac 必须有授权本应用 `keychain-access-groups` 的内嵌开发描述文件，临时签名不能替代。
2. 在仓库执行 `python3 Scripts/create-pair-bootstrap.py`。文件写入被忽略的 `build/private/pairing/WristControl-Pairing.json`，权限仅当前用户可读写。脚本不打印密钥；同路径已存在就拒绝覆盖。
3. 退出两端腕控。将该文件分别复制到 Mac 的 `~/Library/Application Support/WristControl/`，以及 Watch 应用数据容器的 `Documents/`。后者可用 Xcode 的开发设备文件接口或 `xcrun devicectl device copy to`，目标必须明确选中这块已配对 Watch 的腕控应用容器。设备 ID 不写进仓库。
4. 启动两端。应用把密钥保存为本应用的数据保护钥匙串条目，设为仅设备解锁时可读、仅本设备保存、不同步。重新读回核对成功后，应用删除自己的导入文件。开发电脑的私有源文件可由设备拥有者离线保管，不能进入 ZIP 发布物或 Git。
5. Mac 显示“设备已认证”才表示双方证明了持有这一对密钥。开发配对、蓝牙已连接和签名成功都不是这个结果的替代品。

不会重置旧 login 钥匙串。读取失败、条目格式异常或保护等级不符时，不能据此授权输出。导入文件与已有密钥冲突时停止导入并保留既有密钥；不删除重建、不自动降级、不弹认证窗口。证书私钥位于开发签名钥匙串，与这个应用内设备密钥是两件事。

本轮没有撤销／换绑界面。如果需要换设备或怀疑密钥暴露，应停止使用并由开发安装者明确处理两端密钥；不能只改广播名称或清空会话号，宣称旧设备已撤销。

## 消息与边界

原有 20 字节动作体保留，协议版本升为 2，加入暂停指令。旧标记指令不能触发系统输出，旧版本裸动作拒绝执行。

双方各产生一次随机数；Mac 和 Watch 分别用 CryptoKit 的 HMAC-SHA256 证明持有密钥。两个证明使用不同标签，覆盖双方随机数；再用 HKDF-SHA256 派生当前蓝牙连接的密钥。每次重连重新生成，旧连接的消息不能认证。

认证后的包包含 8 字节递增计数器、动作体和完整 32 字节认证码。认证范围同时包含方向和用途（输入、状态、诊断），不能把通知反射成输入。收到的计数器必须比上一条大，准备／暂停状态也受防重放保护。这里提供消息认证，**没有声称应用层消息加密**。

典型动作包为 60 字节，本轮要求短 ATT 负载能够容纳；数据长度不足就停止连接，不降级到未认证模式。诊断分块按实际短写上限计算，不依赖长写分片可以被当成一条完整动作。

动作仍受原有会话号、单调序号与 Mac 发出的 350 毫秒有效许可约束，不相减两端时钟。待发送滚动最多一份，超过 80 毫秒丢弃；反向、停手和断线清空。任何已经观察到的资格丢失立即更换控制会话，恢复只接受新动作。滚轮的小数部分仅在同一连续方向中累计，停止、反向和资格变化均清空，没有惯性队列。

## 锁屏与权限

每次实际提交前检查发送事件权限、睡眠／显示器／登录会话状态、AppKit 保护数据状态，并真正无交互读取受保护的钥匙串数据。仅查“条目是否存在”或只听显示器睡眠通知不足以说明已解锁。失败就停止并清掉旧意图。

这组公开接口的组合仍必须在实际 Mac 上做锁屏验证；不能把编译通过写成所有锁屏方式都已验证。程序没有使用未公开的锁屏字典键或私有通知。检查与提交也不是操作系统提供的不可分割操作。

## 一次集中验收

1. 脱离 Xcode 调试器运行；只启动 `/Applications` 中的一份 Mac 腕控和真实手表腕控。先开权限再继续滚轮。
2. 浏览器长文：指针在正文，慢转、快转、停手、立即反转；记录方向与小幅输入。将腕控最小化再重复。
3. 非浏览器应用：用长文文本文件在文本编辑中重复。切应用不应使腕控暂停，指针位置仍决定接收区域。
4. 暂停后转动不能滚动，继续后不能补放。停顿 30／60／180 秒，放下手腕，切到表盘再返回，各记录首次输入及唤醒步骤。
5. 测试仍亮屏时锁屏；在锁屏期间转动，解锁后检查没有旧动作补放。显示器唤醒但未解锁、撤销权限也分别测试。
6. 蓝牙断线、电脑应用重开后重新认证；旧动作不能补放。导出诊断记录，检查两端内容是否齐全。

自动测试覆盖的是计算和状态规则；同机日志用于定位程序收到至提交的时间。用一个镜头同时拍表冠与电脑画面才可估算真实响应，不拿提交日志当成画面刷新。
