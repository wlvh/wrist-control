# 0.3 G1：A＋点击首个安装候选（build 3）

关联 #2，集成 PR #6。G0 为 `2d5dbf0`；本候选只在手表展示 A 模式。B/C/D 和练习模块已经同仓编译、自动测试，尚未接入完整入口；不因此宣布四模式交付。

生产链：一个前台 Core Motion 流请求 50 Hz → 约 30 Hz 最新姿态快照 → 认证的同一 BLE 输入特征 → Mac 移动周期和映射 → 公开 CGEvent。A 使用包裹方向差，起点为当前姿势与当前光标；开启后留 120 ms 再取得三份稳定样本。屏幕按钮开启移动，本构建未绑定互点。

通信调整的依据是已保存的 0.2 真机日志中 339 份应用确认，单 Watch 时钟往返中位数约 60.04 ms；逐包等待应用确认的上限约为 16.7 次/秒。此数据是历史串行链路证据，**不是 0.3 延迟结果**。最小改动只让绝对姿态快照使用同一特征的 writeWithoutResponse；控制/滚轮/点击仍可靠发送，计数器仍串行分配。增量滚轮继续合并，不能只保留最后一条。新构建的每秒采样与发送/接收计数必须再从实际运行记录读取。

生产输出前仍检查认证、权限、电脑可交互状态和输出范围。点击先冻结当前已处理光标，再发一对；左键第二触仅在 Watch 触摸间隔、Mac 提交间隔及冻结位置均符合时发 clickState=2 的第二对。首触不等待双击窗口。先准备完整事件对；若 down 后资格丢失，唯一例外是有限的一次匹配 up 清理。无拖拽、键盘、目标应用检查或鼠标抢焦点。

- 自动测试：`swift test --scratch-path build/root-tests`，直接调用生产映射、状态、协议、输出和评分实现。
- 原生构建：两个 scheme 的 generic 目标；真机签名复用原开发证书、bundle ID、访问组与配对密钥。
- 记录：每次运行保留 runID、版本、build、源码 SHA；设备时钟分别记录，不相减；事件提交不等同画面或应用动作成功。
- 独立审查已修：竖直跨极点假跳变、被拒首击污染双击、较早停止拒绝吞掉总暂停、开始被拒后卡在准备。Mac 本地模式/隔离入口在后续接线时须先替换逻辑会话，不能仅冻结当前周期。

## 集中的首次实体步骤

1. 在手表前台打开腕控，必要时点“继续腕控”。把 Mac 鼠标留在安全的空白区域。点“开启移动”，停稳片刻，再轻微向右和向上转手腕；确认方向和停止按钮。
2. 再次开启移动，把光标移到访达一个测试文件。点一次左击，确认选中且移动已冻结；同一位置连续点两次左击，确认打开；点右击，确认菜单。测试文件应无副作用，不选删除或危险命令。
3. 重新开启移动，转表冠，确认先冻结再滚动；停手后不重新移动。总暂停必须同时禁止移动、滚轮与点击。停止移动仍允许滚轮和点击。
4. Mac 窗口最小化、手表前台的条件下再试。启动不附加 LLDB，分别记录屏幕按钮和后续互点的结果。

结果保持待真实设备输入确认。若方向相反、手腕偏置或系统接管妨碍使用，记录实际姿势与设置，不要求用户迁就未经验证的轴约定。
