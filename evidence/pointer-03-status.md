## 安装与连接故障的实际过程

1. 原开发描述文件已经过期，原证书仍有效。Xcode 账号重新登录后正常续签，没有新建配对密钥。通用 Watch 构建的 profile 起初只含另一条设备记录，实际安装被 0xe8008012 拒绝；指定原物理 Watch 自动更新 profile 后，确认它包含目标，再安装启动成功。
2. Mac 原有应用密钥读取返回 item-not-found。确认新旧应用访问组与身份完全相同后，复制本机原始私有安装材料进行恢复；应用验证导入后删除临时文件。没有重新生成随机密钥。此举只证明该密钥成功导入，不代表本轮双向认证已通过。
3. 两端重启仍失败。Watch 记录 connect_failed，Mac 蓝牙系统同时记录加密失败和 MIC failure。用户授权只重建该 Watch 与 Mac 的开发配对；旧记录移除后通过独立 Device Hub 重新配对，并核验为原物理 Watch、paired / connected。随后 G1 重试仍失败，说明开发配对重建没有解决运行时连接。
4. 源码中，应用密钥/HMAC失败使用了 ATT 的 insufficientAuthentication 错误。这混淆了应用认证与蓝牙链路认证；G2 改为普通请求失败，同时缺少可用应用密钥时不开始广播。修正版效果待实测，**不能把这一关联写成已证实的 MIC 根因**。
5. 本机 Xcode 27.1 的 Window 菜单没有 Device Hub；实际独立入口是 `/Applications/Xcode.app/Contents/Applications/DeviceHub.app`。旧菜单指引已纠正，见[设备互联记录](../docs/device-connection-notes.md)。

原始日志、设备标识、profile、签名选择与配对材料均位于忽略的私有目录。公开报告不附原始身份或轨迹。

build 4 的签名等待后来返回成功，两个构建日志均为 `BUILD SUCCEEDED`，产物版本／源码标记与严格签名校验一致；没有因此新建证书、私钥或配对密钥。安装成功不能替代启动或 BLE 成功。另已从原 `253ff29` 归档源码，在当前 Xcode 分别完成 0.2 Mac／Watch 无签名构建，验证回退源码仍可编译；尚未重新签名或安装该回退构建。

## 软件审查和自动检查覆盖

独立审查发现并已修复：隔离窗口因参考变化退出后迟到点击可能被路由为系统点击；本地换会话先发布旧 scope；设置页资格在新会话中未同步；参数变化导致比较记录过期；D 因普通鼠标跨屏误删标定；保留模型的新会话首帧未直接校验参考。实际生产类回归覆盖这些路径，审查未留下已知可复现 P1/P2 阻断。

另外覆盖：A/B 动作轴与跨极点、C 回中／断流、首击立即与第二击仅第二对、失败点击不重放、down 后有限 up 清理、旧会话／周期、姿态和滚轮小量、显示器偏移与 Retina、q/-q、D 退化拟合与固定锚点、盲指不裁剪误差、目标失败保留。原生系统提交函数在这些测试中被替换为记录函数；它们不是实际鼠标事件或真机链路。

G2 相对运动在周期开始读取实际光标，随后累计已接受目标并裁剪，避免系统尚未反映上一条 CGEvent 时丢失增量。移动中点击冻结该最后接受目标；已停止时读取实际光标。没有排队补放或自动恢复。

互点代码使用公开 primaryAction 快捷手势，绑定同一个移动按钮；默认关闭，先完成屏幕按钮验证后由用户开启。屏幕按钮与互点的真实结果仍分别待验证。
