# 第一阶段证据边界

这份公开摘要对应“腕控”在一组本地设备上的初次验证。设备名称、序列号、签名团队、钥匙串和逐事件日志没有发布。原始证据由设备拥有者保留在本机。

| 检查 | 已观察到的结果 | 尚不能推出的结论 |
| --- | --- | --- |
| Xcode 真机目标构建 | Mac 与 Watch 签名构建、安装均通过 | 适合正式分发 |
| 共享规则测试 | 11 项通过 | 真机手感或画面延迟 |
| Watch 模拟器 | 安装与启动通过 | 真实蓝牙与表冠输入 |
| 真实 Watch 到 Mac | 电脑处理 537 条滚动、25 条停手消息、3 条标记；正向 273、反向 264 | 完整长文体验已验收 |
| 双端消息对应 | 376 条发送与接收按会话和序号对应，其中 375 条控制消息、1 条 hello | 两端时钟可直接比较或画面已绘制 |
| 诊断 | Mac 文件导出并在访达选中通过；双端原始日志分别从本机取回 | 原生蓝牙双端导出已通过 |

电脑本轮原始日志没有截断；手表保留 3723 条事件，较早的 2000 条达到容量后被截去。会话与序号对应是通信证据，不是准确的动作到画面延迟。电脑记录的“已处理”也不等于屏幕已经绘制。

真机日志中三次断开均对应当前应用的 `app_policy_disconnect_nonactive` 策略。30 秒、1 分钟、3 分钟停顿后的首次操作，及放下手腕后的恢复，还需要按正常姿势分别测试。完整阅读是否减少伸手操作，最终由使用者判断。

[独立代码审查](phase1-review.md)没有发现试用前的阻断问题。此次审查没有替代新一轮真机体验，也没有验证正式分发。
