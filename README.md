# 腕控 WristControl · 第一阶段验证版

Apple Watch 通过 CoreBluetooth 直接连接 Mac。转动数码表冠，滚动本应用窗口内的一篇编号长文；点击手表按钮，在电脑文章中留下阅读标记。运行时没有手机中继、云服务或脚本服务。

这是一次阅读体验验证。当前实现只修改自己的文章窗口，不控制浏览器或其他应用，也不申请辅助功能权限。蓝牙连接和会话号**不能证明设备身份**；可信配对是后续阶段在控制其他应用之前必须完成的工作。

## 当前证据

已使用真实 Apple Watch Series 12 / watchOS 27 和 Mac 完成安装与基础链路测试。电脑记录到 537 次正反向滚动、25 次停手消息和 3 次标记；两端有 376 条消息能按会话与序号对应。共享逻辑有 11 项自动测试通过。

这些结果证明基础输入、蓝牙消息和测试窗口输出曾实际工作。尚需验证完整长文阅读是否舒适、停顿与放下手腕后能否顺畅继续，以及手表在线时的原生双端诊断导出。没有测得动作到屏幕画面的精确延迟。原始真机操作日志保留在开发电脑上，公开仓库只提供不含设备标识的汇总，详见 [证据边界](evidence/STATUS.md)。

## 构建与安装

需要支持目标设备系统的正式版 Xcode 和一台 Mac。打开 `WristControl.xcodeproj`，先用 `WristControl` scheme 在 Mac 上构建、运行电脑窗口，再用 `WristWatch` scheme 安装到真实手表。真机安装需要在 Xcode 中登录自己的开发团队、启用设备开发者模式并完成配对；签名账号和系统授权由设备拥有者操作。

仓库不包含签名身份。将 `Config/Local.xcconfig.example` 复制为被 Git 忽略的 `Config/Local.xcconfig`，填写自己的 Team ID 和唯一的 bundle 前缀，或者在 Xcode 中选择开发团队。证书私钥、配置、描述文件和设备标识不得提交。首轮真机仅使用开发签名，没有做正式分发。

不签名编译和共享规则测试可用以下命令复现：

```sh
swift test --disable-xctest --enable-swift-testing
xcodebuild -project WristControl.xcodeproj -scheme WristControl -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project WristControl.xcodeproj -scheme WristWatch -destination 'generic/platform=watchOS' CODE_SIGNING_ALLOWED=NO build
```

这些命令的成功不代表真实设备已安装或蓝牙链路已通过。本轮真实设备证据与自动测试分开记录。

这次电脑、手表和手机的开发配对、安装连接与运行时蓝牙路线，及实际遇到的代理和重复实例问题，记录在[首次真机联调笔记](docs/device-connection-notes.md)。

## 试用方式

1. 从“应用程序”打开 Mac 腕控，保持编号长文窗口可见，并只运行这一份电脑应用。
2. 在手表前台打开腕控。显示“可控制测试窗口”后慢转、快转、停手、立即反转，并按一次“留下阅读标记”。
3. 按平常的放松姿势读文章，分别停顿 30 秒、1 分钟、3 分钟再转动；放下手腕、切到表盘后再返回，记录首次输入是否生效和需要的操作。
4. 先点电脑“导出诊断”保存这段阅读记录，再测试退出重开应用和蓝牙中断恢复。新进程会产生新的日志，导出文件由访达直接选中。

诊断会明确标记缺少手表日志的情况。日志仅用于定位输入、连接和窗口输出，不把两台设备的时间戳直接相减，也不把电脑处理完成当成屏幕已经画出。

## 实现边界

- `WatchApp/`：SwiftUI 界面、表冠输入、前台蓝牙发现与连接。
- `MacApp/`：AppKit 长文窗口、蓝牙服务、仅作用于本窗口的滚动和标记。
- `Shared/Sources/WristCore/`：20 字节消息定义、线性滚动计算、会话与过期动作规则。
- `Tests/WristCoreTests/`：小数输入、回绕、反向、重复消息和旧会话等规则测试。
- `evidence/`：可公开的结果摘要与独立审查边界。原始设备日志在本地私有目录，不进入公开 Git 历史。

滚动采用线性映射，没有惯性或自动滚动。手表应用进入非活动状态时，当前代码会主动停止扫描并断开；恢复体验需要用真实阅读姿势评估。没有伪装运动、音频或其他后台会话，也没有任意按键、程序执行或系统输入接口。

只有用户在真实姿势下读完文章，认为它减少伸手且停顿恢复不麻烦，才考虑第二阶段。届时再处理身份验证、浏览器目标、权限和日常入口。
