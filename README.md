# 腕控 WristControl · 0.3 自用实验

Apple Watch 的表冠控制 Mac 普通上下滚轮，手腕控制指针，手表按钮执行左击、双击和右击。同一个 Mac/Watch 版本提供四种方式，供使用者亲自比较。工作集中在 [Draft PR #6](https://github.com/wlvh/wrist-control/pull/6)，对应 [#2](https://github.com/wlvh/wrist-control/issues/2)、[#3](https://github.com/wlvh/wrist-control/issues/3)、[#4](https://github.com/wlvh/wrist-control/issues/4)、[#5](https://github.com/wlvh/wrist-control/issues/5)。未经使用者授权，不合并、不正式发布、不关闭未验收任务。

**当前证据边界：** G1 的 0.3.0 build 3 已完成两端签名、真机安装和无调试器启动，但使用者反馈反复断线，尚未完成 A＋点击验收。已恢复原有应用密钥；后续系统日志仍报告蓝牙加密／完整性校验失败，开发配对已按授权重建，但运行时连接重试仍失败。四模式接线及自动测试继续推进，不能将它们写成真实手感已通过。[本轮状态](evidence/pointer-03-status.md)区分安装、提交、真实效果和待验收项。

## 怎样使用

| 模式 | 手腕动作 | 光标行为 |
| --- | --- | --- |
| A 转向跟手 | 向左右转向、上下改变朝向 | 角度变化对应移动量；停住即停 |
| B 翻转跟手 | 前臂向内／向外翻转，加上下朝向变化 | 使用与 A 不同的动作轴；不是另一档速度 |
| C 倾斜摇杆 | 从舒适中立姿势偏转 | 偏着持续走，回中停止；断流停止 |
| D 指向定位 | 固定坐姿与支撑点，先做五点标定 | 朝向对应标定屏幕上的绝对位置；开启可对齐指向，不点击 |

1. 保持手表腕控在前台，认证完成后点“继续腕控”。Mac 每次启动默认总暂停。总暂停影响移动、滚轮和点击。
2. 在手表点“开启移动”，停稳片刻再操作。A/B/C 从当前光标与姿势开始。移动开启时由手腕连续控制；需要使用触控板重新定位时，先停止手腕移动。
3. 点“停止移动”后仍能滚轮和点击。点击或首次有效表冠输入也会先冻结移动；结束后不会自动重开。左击首触立即提交一对按下／松开，第二触符合系统间隔且位置不变时只增加第二对。没有拖拽或保持按下。
4. 先确认屏幕按钮能正常移动和停止，再在手表设置中开启“互点两下启停移动”。互点仅绑定同一个移动按钮，不绑定总暂停或点击；默认关闭，以便分开验证。系统支持、解锁、抬腕和实际姿势仍需真机确认。
5. 手表设置或 Mac 模式菜单可切换四模式；切换先停。A/B 速度分别保存；C 的中立区、满速角、曲线和最高速度在 Mac“模式参数”调整。D 不提供破坏标定关系的速度增益。
6. D 在 Mac 点“五点标定 / 重校”：按中心和四角目标倒数自动采集，不用逐点触碰手表确认。完成后进入独立盲指入口。参考重建、布局／缩放、佩戴等改变会失效；换坐姿、支撑点或屏幕角度时应主动重校，应用不能自动识别所有姿势变化。

**滚轮遵循普通鼠标规则：鼠标放在哪里，就滚动哪里。** 不识别浏览器、不抢焦点、不读网页内容。Mac 窗口最小化或普通应用切换不停止系统输入。标定与练习只作用于腕控自己的窗口，退出时也不恢复旧移动。

## 比较与记录

Mac“练习与同版比较”提供每模式 4 个练习、20 个正式目标，目标直径 24／48／96 个屏幕逻辑单位；不同轮次提示不同模式顺序，也可用普通鼠标作参照。失败、超时、中止和主观费力都保留。改模式或改参数会中止当前轮，下一轮记录实际条件。

D 的五点训练残差、九点独立盲指、看着光标修正的成绩和姿势扰动分别记录。盲指先锁定预测，再显示落点；不能把反复修正后的命中当作自然盲指准确。用 Watch 左击可请求内部锁定，不向系统提交这个点击。详见[比较说明](docs/pointer-validation.md)。

两端日志带运行编号、build、源码 SHA、动作序号和本地时钟；Mac 从认证消息读取 Watch 的 build/SHA。每轮练习和标定原始采样存放在本机 Application Support/WristControl 下，限额后保留旧记录；练习提示导出，标定写入失败记入本地诊断。原始记录不进入公开仓库。电脑“导出诊断”一次保存两端可取得的日志；缺少手表日志会明确标记。

系统事件已提交不代表目标应用已完成动作；处理耗时、蓝牙往返、动作到画面延迟分开报告。**不得直接相减两设备的时钟。** 真实画面延迟需同一镜头或其他经过验证的共同时间基准。

## 构建、安装与回退

- 使用支持现有真机系统的 Xcode，不自动升级系统。复制 `Config/Local.xcconfig.example` 到忽略的 `Config/Local.xcconfig`，填入自己的开发团队和 bundle 前缀。已有安装保持原标识、访问组和证书。
- 打开 `WristControl.xcodeproj`，构建 `WristControl` 和 `WristWatch`。Mac 使用本地开发签名及数据保护钥匙串描述文件，不启用 App Sandbox。Watch 的开发描述文件必须包含实际手表；通用构建成功不证明该设备可以安装。
- 两端安装同一 build，Mac 固定在 `/Applications/WristControl.app`，只运行这一份。由拥有者确认蓝牙、运动以及 Mac 发送事件所需的系统权限。登录、密码和系统确认只在苹果窗口完成。
- 新的设备对按[单对设备配置](docs/system-wheel.md)配置一次随机密钥；**升级不生成新密钥。** 读取失败先区分锁定、访问组不匹配和不存在；仅在有原始材料时恢复原来那份密钥。导入验证成功后临时文件删除。密钥不进源码或通用包。
- 开发安装可以经 iPhone 建立信任和设备准备，运行时始终是 Watch → BLE → Mac，没有手机或网络中继。开发配对、开发安装和应用认证是三件事，参见[互联笔记](docs/device-connection-notes.md)。
- 0.2 的源码保留在 `253ff2971d18fb4170b4abc2f32573339bb8a311`，本机还有 `rollback/0.2-253ff29` 及私有 Git bundle。需要回退时从该 ref 建独立目录，复用原本地签名配置正常续签两个 scheme；不依赖过期安装包，不重置钥匙串或配对密钥。

```sh
swift test --scratch-path build/tests
xcodebuild -project WristControl.xcodeproj -scheme WristControl -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project WristControl.xcodeproj -scheme WristWatch -destination 'generic/platform=watchOS' CODE_SIGNING_ALLOWED=NO build
```

无签名编译不是可使用的安装包。实际安装构建另加 `-allowProvisioningUpdates`，并传 `WRIST_SOURCE_REVISION=<完整提交SHA>`；Watch 首次续签应指定真实设备并允许 Xcode 注册设备。`Scripts/generate-project.py` 可重建工程；开发配置和所有原始设备／签名材料均被忽略。

## 支持边界与历史

只用公开 SwiftUI、Core Motion、CoreBluetooth、AppKit 和 CoreGraphics 接口。共享采集、认证与输出；相对位移在周期内累计后提交绝对目标，屏幕边缘丢弃超界量；停止后不补放旧运动或点击。C 只按新样本的同设备有效时间差积分。D 的磁盘诊断记录不会自动激活为新会话中的有效模型。

手表非活动时仍停止扫描、采样和连接，没有伪装运动／音频后台会话。没有摄像头、键盘、云端、任意命令、浏览器扩展、应用目标锁定、惯性或拖拽。放腕、阅读停顿、系统翻腕和互点条件是否适合实际姿势，必须如实记录。

0.2 曾由使用者确认 Edge、Finder、聊天滚动和锁屏后无补滚，见[历史 0.2 证据](evidence/system-wheel-status.md)；0.1 的测试窗口证据见[历史记录](evidence/STATUS.md)。它们不能替代本轮指针／点击或四模式比较。
